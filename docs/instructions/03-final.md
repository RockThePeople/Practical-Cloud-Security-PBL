# 단계 03 — 최종 정리: README 결과 절, 슬라이드 원고, 발표 대본

## 목적
단계 01·02의 결과를 제출용으로 정리한다. 최종 결과에는 다음 4가지만 담는다: **탐지 결과, 정상/공격 구분 근거, 오탐·미탐 분석, 한계**.

## 하지 않는 것
- 탐지 규칙, 평가 방식, 데이터는 바꾸지 않는다. 숫자는 `evaluation/results/*.json`의 값을 그대로 쓴다.
- 새 실험은 하지 않는다. 예외는 아래 2번의 기술 통계 하나뿐이다.
- 루트 `README.md`의 기존 줄은 고치거나 지우지 않는다. 맨 끝에 덧붙이기만 한다. 그 밖의 원본 파일은 단계 00 규칙 그대로 건드리지 않는다.
- PPTX 같은 바이너리 슬라이드 파일은 만들지 않는다(원고만 쓴다).

## 할 일

### 1. 지시서 저장
이 문서를 `docs/instructions/03-final.md`로 저장한다.

### 2. 구분 근거용 기술 통계 — `evaluation/describe.py`
`data/`만 읽어서 시나리오별로 다음 값을 계산하고 `evaluation/results/03-describe.json`에 저장한다.
- 감시 SA의 출발지 IP 집합, UA 집합
- 실행 1회당 요청 수와 초당 요청 수(첫 요청부터 마지막 요청까지 시간으로 나눈 값)
- 조회한 (verb, resource, subresource) 집합, 403 수, 이름 지정 요청 수

이 값은 설명에만 쓴다. 탐지 규칙에는 넣지 않는다.

### 3. 루트 README에 절 추가
`README.md` 끝에 `## Category 3 결과 — Kubernetes Audit Log 기반 SA 오용 탐지` 절을 덧붙인다. 순서는 아래와 같다. 각 소절은 짧게 쓰고, 자세한 내용은 `docs/reports/`로 연결한다.
1. **요약 (3줄):** 무엇을 만들었고, 핵심 숫자가 무엇인지
2. **실행 방법:** 테스트, CLI(`--mode`), 평가, 데이터 다시 수집(클러스터 필요)
3. **데이터:** 시나리오 5종 × 5회. `normal_misconfig`가 왜 있는지 한 줄. 라벨은 파일 단위
4. **정상/공격 구분 근거:** 2번 통계로 "구분에 쓰지 않는 것"(IP, UA, 속도, 토큰 ID)과 "구분에 쓰는 것"(리소스, subresource, 이름 유무, 응답 코드, 허용 목록, 시간적 묶음)을 표로 보인다
5. **탐지 기준:** 기본 R1~R3와 보완 1~3의 규칙 표, severity 설명 한 줄
6. **탐지 결과:** 최종 비교표 6행. 용어(TP/FP/FN/TN, precision, recall, 반사실)를 표 아래에 한 줄씩 설명한다. 반사실은 "Role이 넓게 잘못 설정된 상황을 흉내 내려고 평가 코드 안에서만 403을 200으로 바꾼 것이며, 실제 권한은 바꾸지 않았다"고 쓴다
7. **오탐·미탐 분석:** 보고서 02의 5절 표를 바탕으로 쓴다
8. **한계:** 보고서 02의 6절을 그대로 옮긴다. 1.000은 같은 데이터로 설계하고 평가한 결과라는 점을 맨 위에 둔다

### 4. 슬라이드 원고 — `docs/presentation/slides.md`
슬라이드 12~14장. 장마다 `제목 / 핵심 메시지 한 줄 / 화면에 넣을 내용(표·숫자·그림 설명)`의 형식으로 쓴다. 흐름은 다음과 같다.
1. 표지
2. 문제: 같은 SA로 정상과 공격이 섞인다. Audit Log만으로 구분할 수 있을까?
3. 테스트베드와 시나리오(4개 + misconfig)
4. Audit Log에서 보이는 것과 쓸 수 없는 것(구분 근거 표)
5. 기본 탐지 R1~R3(README 관찰점)
6. 기본 탐지 결과
7. 한계 1: 조각으로만 본다(놓친 65건, abnormal_3 사건 12개)
8. 한계 2: 403이면 무조건 의심(misconfig 오탐 5/10)
9. 한계 3: 최소 권한이 깨지면 놓친다(반사실 개념 설명)
10. 보완 1~3 규칙
11. 최종 비교표. u12 반사실(0.429)과 u123 반사실(1.000)의 대비를 강조한다
12. 오탐·미탐 분석
13. 남는 한계
14. 정리(한 문장 결론)

그림이 필요한 장은 그림 설명만 쓴다(예: abnormal_3 요청 18건을 시간축에 놓고 C1이 묶는 범위를 표시).

### 5. 발표 대본 — `docs/presentation/script.md`
